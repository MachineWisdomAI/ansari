The insert is raw SQL `INSERT … VALUES … ON CONFLICT (id) DO NOTHING` followed, in the same transaction, by a tombstone read that rolls it back (consult iter3; originally a `WHERE NOT EXISTS`, which MVCC defeats), so a concurrent delete cannot be undone. `password_hash` stays NULL (needs 0011). A unique violation (an email race) re-checks the holder and refuses.
- `lib/auth/require-user.ts`: the drop-in `{user}|{error}`. Its details are the frozen legacy ones: no bearer → `Not authenticated`; not verified → `Invalid or expired token`; refused (tombstone, unknown sub, conflicts) → `Token not found or expired` (the phase 1 obligation). A first-use outage → 503 `Authentication service unavailable`, never 401, so an outage does not log clients out.
